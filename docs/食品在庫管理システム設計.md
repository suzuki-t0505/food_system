# **食品在庫管理システム 基本設計書**

## **1\. システム概要と基本方針**

食品特有の「消費期限・賞味期限管理」および「荷姿（ケース・バラ）管理」に対応した、複数倉庫向けの在庫管理システム。

### **📌 コア要件まとめ**

| 項目 | 決定仕様 | 備考 |
| :---- | :---- | :---- |
| **在庫管理単位** | **ケース数** と **バラ数** を明確に分けて独立管理 | 画面表示・帳票出力時は「バラ換算の総数」も自動計算して併記する |
| **ケース入数** | 商品マスタにて **固定値** として保持 | 総バラ数 ＝ (ケース数 × 入数) ＋ バラ数 |
| **先出し後入れ基準** | **第1優先：期限日（昇順） ➔ 第2優先：入荷日（昇順）** | FEFO（期限順）＋ FIFO（入荷順）のハイブリッド |
| **期限管理区分** | 商品マスタにて **「消費期限」「賞味期限」「管理なし」** を区分 | 期限アラート通知は将来拡張機能としてカラムのみ先行用意 |
| **出庫引当方式** | **自動引当（方式A：荷姿厳守＋期限順）** | 将来的に「自動引当＋ピッキング実績消し込み」へ拡張可能なDB構造とする（引当と実績のロット逆転は起こらない前提） |
| **荷崩し処理** | **完全自動（パターンA）** | バラ出庫引当時にバラ在庫が不足した場合、システムが自動で古いケース在庫を1ケース単位で開封（ケース減・バラ増）して引き当てる |
| **複数倉庫対応** | 出庫時は **オーダー時点で対象倉庫を指定** | 倉庫間移動は「移動中ステータス」を持たず、**即時反映**（元の期限日・入荷日を移動先へそのまま継承） |

### ---

**④ 在庫ロット (inventory\_lots) 【★システムの心臓部】**

「倉庫 × 商品 × 期限日 × 入荷日」の粒度で現在庫と引当済数を保持します。

| カラム名 (論理名) | カラム名 (物理名) | 型 | 制約 / 説明 |
| :---- | :---- | :---- | :---- |
| ロットID | lot\_id | BIGINT | PK |
| 倉庫ID | warehouse\_id | BIGINT | FK (warehouses.warehouse\_id) |
| 商品ID | item\_id | BIGINT | FK (items.item\_id) |
| **期限日** | expiration\_date | DATE | 消費期限 または 賞味期限（管理なしの場合は 9999-12-31 等） |
| **入荷日** | received\_date | DATE | NOT NULL（倉庫間移動時も元の入荷日を維持） |
| **現在ケース数** | case\_qty | INT | NOT NULL (DEFAULT 0\) |
| **現在バラ数** | piece\_qty | INT | NOT NULL (DEFAULT 0\) |
| **引当済ケース数** | allocated\_case\_qty | INT | NOT NULL (DEFAULT 0\) ※出荷待ちロック分 |
| **引当済バラ数** | allocated\_piece\_qty | INT | NOT NULL (DEFAULT 0\) ※出荷待ちロック分 |

> * 💡 **複合ユニーク制約**：UNIQUE (warehouse\_id, item\_id, expiration\_date, received\_date)  
> * 💡 **有効在庫（引き当て可能な数）の計算式**：  
  * 有効ケース数 \= case\_qty \- allocated\_case\_qty  
  * 有効バラ数 \= piece\_qty \- allocated\_piece\_qty  
  * 有効総バラ数 \= (有効ケース数 × units\_per\_case) \+ 有効バラ数

**⑥ 在庫受払履歴 (inventory\_transactions)**

すべての在庫変動（自動荷崩しや倉庫移動を含む）の完全な証跡ログです。

| カラム名 (論理名) | カラム名 (物理名) | 型 | 制約 / 説明 |
| :---- | :---- | :---- | :---- |
| 履歴ID | transaction\_id | BIGINT | PK |
| ロットID | lot\_id | BIGINT | FK (inventory\_lots.lot\_id) |
| 処理区分 | transaction\_type | ENUM | RECEIVE(入荷) / SHIP(出庫) / AUTO\_BREAK(自動荷崩し) / TRANSFER\_OUT(移動出庫) / TRANSFER\_IN(移動入庫) / ADJUST(棚卸調整・廃棄) |
| 変動ケース数 | case\_diff | INT | 増減値（例：荷崩しなら \-1） |
| 変動バラ数 | piece\_diff | INT | 増減値（例：10入りの荷崩しなら \+10） |
| 関連オーダーID | reference\_id | BIGINT | NULL可（出庫オーダーIDなどを紐付け） |
| 処理日時 | created\_at | TIMESTAMP | NOT NULL |

**3\. コア業務ロジック仕様**

### **🔄 ロジック①：出庫時の自動引当 ＆ 自動荷崩し（方式A × パターンA）**

ユーザーが **「出庫倉庫」「商品」「要求ケース数 (req\_cases)」「要求バラ数 (req\_pieces)」** を指定してオーダーを登録した際、単一トランザクション内で以下の順に処理します。

> 1. **対象ロットの取得とソート**  
   * 指定された warehouse\_id かつ item\_id のロットのうち、期限切れでないものを抽出。  
   * ソート順：**ORDER BY expiration\_date ASC, received\_date ASC, lot\_id ASC**  
> 2. **【ステップ1】ケース要求分 (req\_cases) の引当**  
   * ソートされたロットを上から順に走査し、有効ケース数 \> 0 のロットから req\_cases を満たすまで引き当てる（allocated\_case\_qty を加算し、引当明細レコードを作成）。  
   * 全ロットの有効ケース数合計が req\_cases に満たない場合は「ケース在庫不足エラー」としてロールバック。  
> 3. **【ステップ2】バラ要求分 (req\_pieces) の引当と自動荷崩し**  
   * 再度ソートされたロットを上から順に走査し、req\_pieces が 0 になるまで以下を繰り返す：  
     1. **既存の有効バラ数から引当**：そのロットに 有効バラ数 \> 0 があれば、可能な限りバラを引き当てる。  
     2. **同一ロット内での自動荷崩し（パターンA）**：まだ req\_pieces が残っており、かつ**そのロットに 有効ケース数 \> 0 がある場合**、不足バラ数を補うのに必要なケース数（通常1ケース）を即座に開封する。  
        * ロットの case\_qty を \-1、piece\_qty を \+入数 に更新。  
        * 受払履歴（inventory\_transactions）に AUTO\_BREAK（ケース \-1、バラ \+入数）を記録。  
        * 増えたバラ在庫から、残りの req\_pieces を引き当てる。  
     3. それでも足りなければ、**次に古いロット**へ進み、同様に「既存バラ引当 ➔ 足りなければそのロットのケースを自動荷崩し」を行う。

### ---

**🚚 ロジック②：倉庫間移動（即時反映・属性継承）**

ユーザーが **「移動元倉庫」「移動先倉庫」「対象ロット（または自動引当）」「移動ケース数」「移動バラ数」** を指定して実行した際の処理です。

> 1. **移動元ロットの減算**  
   * 移動元倉庫の対象ロットから、指定されたケース数・バラ数を減算（バラ不足時は出庫時と同様に自動荷崩しを行うか、指定ロットの保有数チェックを行う）。  
   * 受払履歴に TRANSFER\_OUT を記録。  
> 2. **移動先ロットへの加算（Upsert処理）**  
   * 移動先倉庫に **「同じ item\_id × 同じ expiration\_date × 同じ received\_date」** のロットが存在するか確認。  
   * **存在する場合**：そのロットの case\_qty / piece\_qty に移動数を加算（UPDATE）。  
   * **存在しない場合**：移動元とまったく同じ expiration\_date と received\_date を引き継いだ新規ロットを移動先倉庫に作成（INSERT）。  
   * 受払履歴に TRANSFER\_IN を記録。

### ---

**🖥️ ロジック③：画面入出力における「総バラ数」の表示仕様**

> * **入力時**：入荷・出庫・移動のすべての画面で、\[ ケース数 \] と \[ バラ数 \] の2つの入力欄を設ける。フロントエンド側で商品マスタの units\_per\_case（入数）を参照し、入力と同時に **総数：〇〇 個** をリアルタイム表示する。  
> * **一覧表示時**：在庫一覧画面では、ロットごと・商品ごとの集計行において常に以下の3列をセットで表示する。  
  * ケース数 ｜ バラ数 ｜ **総バラ数 (ケース×入数＋バラ)**
