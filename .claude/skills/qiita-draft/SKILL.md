# Qiita ドラフト作成スキル

実装中の失敗・エラー解決の経緯を、Qiita に投稿できる形のドラフトとして `docs/qiita/` に残すためのスキルです。
**作るのはドラフトまで**。Qiita への投稿はユーザーが手動で行います（このスキルから投稿はしない）。

## 実行フロー

### 1. 題材の特定

- 引数で題材が指定された場合はそれを使う（例: `/qiita-draft Credo の入れ子の深さ警告`）。
- 指定がない場合は、次の順で候補を集め、**1 記事 1 テーマ**になるように題材を選ぶ。候補が複数あれば一覧を示してユーザーに選んでもらう。
  1. 今の会話で起きた失敗・エラーと、その解決
  2. 直近のコミット（`fix:` や `Revert` を含むもの）

     ```bash
     git log --oneline -30
     git log --grep='^fix' --grep='Revert' -i --oneline -30
     ```
  3. `.steering/` の直近の `tasklist.md` に残っている、つまずきや方針変更の記録

### 2. 事実の収集

推測で書かない。次を実物から確認する。

- **エラーメッセージ**: 実際に出た文言（会話・CI ログ・コミットメッセージから）。再現できるならコマンドを実行して取り直す
- **原因**: 該当コードと、直したコミットの差分（`git show <hash>`）
- **解決方法**: 修正前後のコード
- **環境**: CLAUDE.md の技術スタックと、`mix.exs` / `mix.lock` などの実際のバージョン

確認できなかったことは本文に書かないか、「未確認」と明記する。

### 3. 既存ドラフトとの重複確認

```bash
ls docs/qiita/
```

同じテーマのドラフトがあれば、新規作成せず既存ファイルに追記・更新する。

### 4. ドラフトの作成

- 置き場所: `docs/qiita/{YYYYMMDD}-{英小文字ケバブケースの題材}.md`（例: `docs/qiita/20261109-credo-nesting-depth.md`）
- 構成: 同じディレクトリの `template.md`（`.claude/skills/qiita-draft/template.md`）に従う
- 書き方:
  - タイトルは「何で困って、どう解決したか」が検索で見つかる形にする（エラーメッセージの要点や技術名を入れる）
  - エラーメッセージは検索に掛かる部分を原文のまま載せる。長いスタックトレースは要点だけに削る
  - コードは問題を再現できる最小限に絞り、修正前・修正後を並べる
  - 「やってみてだめだったこと」も書く（同じ所でつまずく読者に役立つ）
  - Qiita の記法を使う（コードブロックは ` ```elixir:lib/foo.ex ` のようにファイル名を付けられる。補足は `:::note info` / `:::note warn`）

### 5. 公開前チェック（必須）

Qiita は誰でも読める。ドラフトを保存する前に、次が本文・コード・ログに含まれていないことを確認し、含まれていれば伏せ字やダミー値に置き換える。

- [ ] 秘密情報（API キー・トークン・パスワード・`SECRET_KEY_BASE`・`.env` の値）
- [ ] GCP のプロジェクト ID・サービスアカウント・バケット名・内部ホスト名・IP アドレス
- [ ] 個人情報（氏名・メールアドレス）、顧客・取引先を特定できる名前やデータ
- [ ] 業務固有の仕様で、公開すると困るもの（一般的な例に置き換える）
- [ ] 非公開リポジトリの URL・Issue / PR へのリンク

### 6. 完了報告

作成したファイルのパスと、記事の要点（題材・原因・解決）を 3 行程度で伝える。伏せ字にした箇所や未確認のまま残した箇所があれば併せて伝える。
